2 · 원천은 세 덩어리뿐

사다리

step-0…12

13칸 · 8 × [0, .5, 1, 1.5, 2, 3, 4, 5, 6, 8, 10, 12, 16]

  • spatial 이 고르는 칸 — 여백·간격
  • visual 이 고르는 칸 — 모서리
  • base를 바꾸면 전부 함께 움직인다
선택 집합

border-width

0 · 1 · 2 · 4  — 사다리 밖

  • 1px은 기기 픽셀에 묶인 값 — 배수로 유도되지 않는다
  • base를 바꿔도 따라 움직이지 않는다
  • “파생 아닌 선택” — 코드에 이미 선언됨
선택 집합

radius.special

9999px · 50%  — 사다리 밖

  • pill = 9999px — 길이가 아니라 “끝까지”
  • circle = 50% — px가 아니라 비율
  • 사다리로 표현 불가능하므로 별도

원천을 나누는 기준은 spatial / visual 이 아니다. “사다리 위인가, 밖인가” 하나뿐이다. spacing·radius·size는 전부 사다리 위에 있고, border-width와 special만 밖에 있다.

3 · 원천이 아닌 것  —  사다리 칸끼리의 산술

size.control{sm,md,lg} = icon.md + 2 × step-{2,3,4}  →  36 · 44 · 52
20 + 2×8 = 36 · 20 + 2×12 = 44 · 20 + 2×16 = 52. 지금은 {type:"linear", base:36, step:8} 독립 규칙으로 선언돼 원천처럼 보이지만, 실제로는 아이콘 슬롯 + 좌우 inset 이다. 규칙을 이렇게 바꾸면 원천이 하나 줄어든다.
child.radius = max(0, radius.container − inset.sm)  →  12 − 8 = 4
중첩 정합(#10). visual 값에서 spatial 값을 뺀다 — 두 원천이 같은 격자 위에 있어야만 성립하는 식. 원천을 나누면 이 규칙(R-2)이 먼저 깨진다.
switch.knob = track − 2 × 2px  /  focus.offset = 2px
헤어라인 정밀값. 사다리 단위(2px)와 같으므로 별도 원천이 필요 없다.

결론. spatial / visual 분리는 이 층 — 시맨틱 — 에서만 일어난다. 원천 층에는 그 단어가 등장하지 않으며, 따라서 dimension 같은 상위 묶음 이름도 필요 없다. 묶을 것이 없기 때문이다.
